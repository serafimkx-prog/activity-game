# Activity — Техническая спецификация по текущему коду

Этот документ описывает **текущее поведение проекта по состоянию кода в репозитории**.

## 1. Стек

- фронтенд: `HTML5`, `CSS3`, `Vanilla JavaScript`
- backend: `Cloudflare Workers`
- база данных: `D1`
- авторизация: `Telegram Login Widget`
- аудио: `Web Audio API`
- данные: JSON-словари и метаданные словарей

Сборщика фронтенда в проекте нет.

## 2. Архитектура фронтенда

Приложение построено как одна страница с несколькими экранами `.screen`.

Переключение экранов делает функция `showScreen(id)`:

1. очищает активный таймер;
2. снимает класс `.active` со всех экранов;
3. показывает нужный экран;
4. скроллит страницу вверх.

Основные пользовательские экраны:

- `screen-setup`
- `screen-rules`
- `screen-profile`
- `screen-turn-start`
- `screen-card-selection`
- `screen-preview`
- `screen-explaining`
- `screen-turn-result`
- `screen-game-over`

## 3. Runtime state

Главное клиентское состояние хранится в `state` внутри `script.js`.

Актуальная структура по коду:

```js
{
  teams: [],
  teamIndex: 0,
  cellMode: null,
  selectedCard: null,
  pools: null,
  indices: null,
  config: {
    turnTime: 60
  },
  timer: null,
  timeLeft: 0,
  gameInProgress: false,
  currentDictionary: null,
  gameStartedAt: null
}
```

Состояние авторизации хранится отдельно в объекте `auth`:

```js
{
  config: null,
  user: null,
  widgetLoaded: false,
  statsLoaded: false
}
```

Дополнительно в `localStorage` используются:

- `activity_active_game_v1` — снимок активной партии для восстановления после `refresh`;
- `activity_pending_game_sessions_v1` — очередь завершённых партий, которые ещё не удалось отправить в backend;
- `activity_dictionary_feedback_v1` — локальный fallback фидбэка по сложности слова.

## 4. Игровое поле

### 4.1. Размер и победа

- игровые клетки: `0..40`
- финиш: `41`
- победа: когда позиция команды становится `>= 41`

### 4.2. Состав поля

Поле создаётся функцией `generateBoard()`.

В массив кладутся:

- `14` клеток `E`
- `14` клеток `A`
- `13` клеток `D`

После этого массив перемешивается алгоритмом Фишера-Йетса.

### 4.3. Визуализация

Поле отображается как змейка в сетке:

- `GRID_COLS = 7`
- `GRID_ROWS = 6`

Функция `pathToGrid(slotIdx)` рассчитывает позицию слота в сетке:

- чётные ряды идут слева направо;
- нечётные ряды идут справа налево.

## 5. Режимы игры

В коде есть три режима:

- `E` → `EXPLAIN`
- `A` → `ACT`
- `D` → `DRAW`

Каждый режим имеет:

- `key`
- `icon`
- `name`
- `css`
- `hint`

Важно: отдельного Canvas-интерфейса для рисования в текущем UI нет. Режим `DRAW` существует как тип задания и визуальная метка клетки.

## 6. Словари

Каталог словарей фронтенд запрашивает через `GET /api/dictionaries`, а backend берёт метаданные из `dictionaries.json`.

Фронтенд:

- показывает доступные, premium- и ещё неоткрытые словари;
- по умолчанию выбирает первый словарь с `canPlay: true`.
- для `geo` без входа показывает CTA `Войти`;
- для premium-словаря без доступа показывает CTA `Купить за 149 ₽` или `Войти, чтобы купить`.

Текущие доступные словари по репозиторию:

- `classic` — free
- `geo` — free after login
- `society` — premium

При старте партии игра загружает JSON-файл выбранного словаря через защищённый asset-fetch:

- `fetch(dict.file)`

Для `geo` Worker требует авторизацию, но не требует покупку. Для premium-словарей Worker проверяет сессию и наличие доступа в `user_dictionary_access`.

После загрузки вызывается `initPools(data)`, которая создаёт перемешанные пулы слов для:

- `DRAW`
- `EXPLAIN`
- `ACT`

и для уровней сложности:

- `"3"`
- `"4"`
- `"5"`

Если конкретный пул заканчивается, `nextWord()` повторно перемешивает уже существующий массив и начинает выдачу сначала.

## 7. Ход игры

Основной игровой цикл:

1. `goTurnStart()`
2. `goCardSelection()`
3. `goPreview()`
4. `goExplaining()`
5. `endTurn()` или `endOpenRound()`
6. `showGameOver()`

### 7.1. Старт партии

По нажатию `Начать игру` код:

- валидирует имена команд;
- собирает списки игроков;
- читает `turnTime`;
- читает `openRoundEnabled`;
- загружает словарь;
- генерирует поле;
- инициализирует команды;
- сохраняет `currentDictionary`;
- сохраняет `gameStartedAt`;
- ставит `gameInProgress = true`.

Во время активной партии фронтенд дополнительно пишет runtime-снимок в `localStorage`, чтобы попытаться восстановиться после обновления страницы.

### 7.2. Ротация объясняющего

Для каждой команды хранится `explainerIdx`.

После обычного хода в `endTurn()` индекс увеличивается по кругу:

```js
team.explainerIdx = (team.explainerIdx + 1) % team.players.length
```

После открытого раунда в `endOpenRound()` очередь объясняющего тоже обновляется для активной команды.

### 7.3. Выбор карточки

Игрок выбирает сложность:

- `3`
- `4`
- `5`

`drawCard(points)` возвращает объект:

```js
{
  points,
  isOpenRound,
  entries: {
    DRAW,
    EXPLAIN,
    ACT
  }
}
```

`isOpenRound` становится `true`, если:

- в конфиге включён `openRoundEnabled`;
- случайное число попало в вероятность `10%`.

### 7.4. Preview

Экран `goPreview()`:

- показывает слово для текущего режима;
- показывает бейдж режима;
- показывает признак открытого раунда;
- запускает countdown на `7` секунд.

После завершения countdown автоматически вызывается `goExplaining()`.

### 7.5. Основной таймер

В `goExplaining()`:

- `state.timeLeft` получает значение `state.config.turnTime`;
- запускается секундный интервал;
- таймер обновляет `#ex-timer`;
- при `timeLeft <= 10` включается urgent-состояние;
- при `timeLeft <= 0` вызывается `onTimerEnd()`.

`onTimerEnd()` не завершает ход автоматически, а только меняет подсказку на экране на сообщение о том, что время вышло.

В setup-экране пользователь меняет `turnTime` через ползунок:

- минимум `30`
- максимум `120`
- шаг `10`
- значение по умолчанию `60`

### 7.6. Восстановление после обновления страницы

При загрузке приложения фронтенд пытается восстановить активную партию из `activity_active_game_v1`.

В снимок входят:

- команды;
- позиции;
- очередь объясняющего;
- выбранный словарь;
- поле;
- словарные пулы и индексы;
- выбранная карточка;
- текущий экран;
- `turnLog`;
- текущий фидбек по сложности.

После завершения партии и после рестарта игры этот снимок очищается.

## 8. Начисление очков и движение

### 8.1. Обычный ход

Если команда угадала:

- получает `points` очков;
- двигается вперёд на `points`.

Если не угадала:

- очков не получает;
- остаётся на текущей клетке.

### 8.2. Столкновение

После успешного обычного хода, если новая позиция не финишная:

- проверяются другие команды;
- любая команда на той же клетке сдвигается на `1` назад;
- позиция не может стать меньше `0`.

В коде проверка идёт через обход всех команд, поэтому при совпадении нескольких команд на клетке сдвинутся все найденные совпадения.

### 8.3. Открытый раунд

В открытом раунде:

- слово угадывают все команды;
- UI показывает кнопки команд и кнопку `Никто`.

Если угадала команда-исполнитель:

- она получает очки карточки.

Если угадала другая команда:

- она получает очки карточки;
- команда-исполнитель получает `+2`.

После движения победителя также проверяется столкновение по той же логике, что и в обычном ходе.

Если нажата кнопка `Никто`, вызывается обычный `endTurn(false)`.

### 8.4. Фидбек по сложности слова

На экране результата хода есть блок `Оценка сложности`.

Игроки могут нажать:

- `Скорее 3`
- `Скорее 4`
- `Скорее 5`

Фидбек привязан к:

- слову;
- режиму;
- исходному уровню карточки;
- результату хода;
- длительности объяснения;
- словарю;
- номеру хода.

Если пользователь авторизован:

- клиент отправляет `POST /api/dictionary-feedback`;
- backend сохраняет запись в D1.

Если backend недоступен или пользователь не авторизован:

- клиент сохраняет fallback-копию в `localStorage`.

## 10. Профиль и статистика

Экран `Профиль` существует как отдельный экран интерфейса.

На клиенте за него отвечают:

- `loadAuthConfig()`
- `refreshCurrentUser()`
- `renderTelegramLoginWidget()`
- `renderAuthCard()`
- `loadProfileStats()`
- `saveFinishedGame(winner)`

Профиль умеет:

- показывать кнопку входа через Telegram;
- показывать текущего пользователя;
- делать logout;
- загружать summary по играм;
- показывать последние игры;
- отправлять фидбек по сложности слов в backend для авторизованных пользователей.

## 11. Backend

Worker entrypoint находится в `src/worker.js`.

Он:

- обрабатывает `/api/*`;
- отдаёт остальное через `env.ASSETS.fetch(request)`.

Поддерживаемые endpoint'ы:

- `GET /api/config`
- `POST /api/auth/telegram`
- `GET /api/me`
- `GET /api/dictionaries`
- `POST /api/logout`
- `POST /api/purchase/create`
- `POST /api/game-sessions`
- `GET /api/profile/summary`
- `POST /api/dictionary-feedback`
- `POST /api/payment/webhook/yookassa`

Сохранение завершённой партии на клиенте теперь устроено так:

- партия сначала ставится в локальную очередь;
- затем фронтенд пытается отправить её в `POST /api/game-sessions`;
- если отправка не удалась, запись остаётся в очереди и повторно отправляется позже.

## 12. Авторизация

Авторизация построена на `Telegram Login Widget`.

Поток по коду:

1. фронтенд запрашивает `/api/config`;
2. если пришёл `telegramBotUsername`, рендерится widget;
3. после login фронтенд отправляет payload на `/api/auth/telegram`;
4. backend валидирует payload через `verifyTelegramAuth()`;
5. backend создаёт или обновляет пользователя;
6. backend создаёт серверную сессию;
7. backend возвращает `Set-Cookie` с `HttpOnly` session cookie;
8. фронтенд читает пользователя через `/api/me`.
