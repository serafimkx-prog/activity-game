## 2026-10-16 — обезличенная аналитика сложности карточек

- Каждый завершённый ход записывает opaque `card_id`, режим, уровень, исход, длительность и open-round flag без текста слова и имён.
- Клиентская очередь ограничена 200 ходами, а отправка идёт пачками до 10 при накоплении, финише, reconnect и page hide; ошибка аналитики не блокирует игру.
- D1-таблица `card_analytics` идемпотентна по `(game_id, turn_number)` и не имеет вторичных индексов, чтобы не умножать стоимость каждой записи.
- Отчёт показывает рейтинг карточек только с 10 наблюдений; `tools/card_analytics_catalog.mjs` сопоставляет opaque id с локальными словарями.

## 2026-10-15 — собственная аналитика партий в D1

- Игровые события перенесены из Яндекс.Метрики в собственную таблицу Cloudflare D1 `game_analytics`.
- Для всех пользователей, включая неавторизованных, считаются запуски, завершения, длительность, число ходов, команды, участники, словари и основные настройки.
- Имена команд/игроков, слова, IP-адрес и содержимое партии не сохраняются.
- Анонимные повторные игры связываются только в пределах одной установки браузера по хешу случайного идентификатора; разные браузеры не выдаются за одного человека.
- Для временных сетевых сбоев используется небольшая локальная очередь событий, а повторная отправка идемпотентна по `game_id`.

Этот файл фиксирует недавние изменения проекта, чтобы их не пришлось восстанавливать по переписке или git diff.

## 7. Надёжное Сохранение Истории Игр

- Завершённая партия теперь сначала ставится в локальную очередь:
  - `activity_pending_game_sessions_v1`
- После этого клиент пытается отправить её в:
  - `POST /api/game-sessions`
- Если отправка не удалась, партия остаётся в очереди и будет отправлена повторно:
  - после следующего успешного входа;
  - при событии `online`.
- На backend добавлена дедупликация `game_sessions`, чтобы повторная отправка не создавала дубль одной и той же партии.
